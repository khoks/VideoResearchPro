Researched 2026-10-18/19. Facts verified by direct fetch of primary sources unless marked **unverified**. Bundle sizes are Bundlephobia "minified / minified+gzip" for the package *including its dependencies* at the stated version. npm metadata is from `registry.npmjs.org`; repo activity from the GitHub API. The web-search budget ran out part-way through; items that could not be re-checked are marked.

## Summary

- **M2 palette:** `cmdk` 1.1.1 (MIT, 14.9 kB gz, unstyled, props forwarded so inline `style` works, `shouldFilter={false}` for server results) is the standard; last release 2025-03-14, repo last push 2025-10-29 — stable but slow. `kbar` 1.0.0 (MIT) finally went stable 2026-08-10 but bundles fuse.js + react-virtual (27.5 kB gz) and ships styled components. `react-cmdk` has no React 19 peer dep — exclude.
- **M2 search backend:** SQLite FTS5 is compiled into python.org Windows and macOS builds and into uv's python-build-standalone; **verified on this machine** (project venv Python 3.12.10 / SQLite 3.49.1: `ENABLE_FTS5`, trigram tokenizer, `bm25()` column weights all work). Linux distro Pythons link the system libsqlite3 — check `PRAGMA compile_options` at startup. Hybrid merge via Reciprocal Rank Fusion (k = 60).
- **M3 scheduler:** no Celery beat runs today. Cheapest sound option is a single static beat entry ("tick every 5 min") that scans a `saved_searches.next_run_at` table — one beat process, no new dependency, `celery.schedules.crontab(...).remaining_estimate()` computes next runs. RedBeat 2.4.2 (Apache-2.0, Redis-backed, dynamic entries, distributed lock) is the upgrade path if per-row beat entries are ever wanted. `celery-sqlalchemy-scheduler` is archived (2022); APScheduler 4 is still alpha (4.0.0a6, 2025-04-27).
- **M3 cron:** `croniter` is alive again — 6.2.4 (MIT) released 2026-07-10 under pallets-eco, no deprecation notice; but cron strings are unnecessary for "daily/weekly" UX and `python-crontab` is LGPL-3.0 (avoid). Prefer human schedules mapped to Celery `crontab`.
- **M3 change detection:** no product documents its algorithm. Perplexity's Scheduled Tasks "stays quiet" when a run finds nothing new and supports user-stated conditions; Google Alerts is keyword-in-index with as-it-happens/daily/weekly frequency. Recommend a cheap gate (no new visible documents since last run → skip) then cited-doc-set Jaccard + answer-embedding distance, with an LLM judge only when the cheap signals disagree.
- **M4:** Bing's WWW 2020 paper (Rosset et al.) is the canonical prior art: "usefulness" over relevance, trained from session next-turn behaviour, +8% clicks in A/B. NotebookLM suggests follow-ups "based on your recent conversation history and the content of your sources". A 5-question batch costs ≈ $0.00014 on gpt-5-nano, ≈ $0.0008 on gpt-4.1-mini (official OpenAI prices, 2026-10-19).
- **M5 data model:** W3C Web Annotation (Rec. 2017-02-23) body/target/selector with `TextQuoteSelector` + `TextPositionSelector` is the interoperable shape; Hypothesis and Readwise map onto it. Editor: plain `<textarea>` + the existing `react-markdown` dependency costs 0 bytes; Tiptap core is MIT (paid parts are Cloud: collaboration, comments, version history, AI) but StarterKit is 106 kB gz; Lexical (MIT) 63 kB gz.
- **M5 retrieval weight:** keep notes in a separate Chroma collection (private, unchunked, deletable) and merge by raw distance using the D-068 formula `distance / weight` with weight 1.5. The app never sets `hnsw:space`, so Chroma's default `l2` (squared L2) applies — the boost is non-linear relative to cosine; measure before tuning.
- **M1:** Zotero (many-to-many collections, flat tags, 9 coloured tags), Raindrop (one collection per bookmark, many tags) and Notion (`select` options with stable `id` + 10 named colours) converge on: collections many-to-many, tags as rows with stable ids, a fixed palette of ~10 named colours, never colour alone. Q&A scoped to a shelf is just the existing `video_id ∈ set` Chroma filter over the union of the shelf's jobs.
- **M6:** The Duplicate flow already defines the parameter set (`jobToFormState` in `SubmitJobPage.tsx`) — a template is that form state persisted server-side with a Grafana-style integer `version`. Postman's rule applies: collection-level values are fixed, environment/data values vary — freeze instructions, filters, channel lists; leave topic and a *relative* date window variable.

### Server-side: SQLite FTS5

- FTS5 is a compile-time option (`SQLITE_ENABLE_FTS5`): https://www.sqlite.org/compile.html
- **Windows (python.org):** `PCbuild/sqlite3.vcxproj` defines `SQLITE_ENABLE_MATH_FUNCTIONS;SQLITE_ENABLE_FTS4;SQLITE_ENABLE_FTS5;SQLITE_ENABLE_PERCENTILE;SQLITE_ENABLE_RTREE;SQLITE_OMIT_AUTOINIT` — https://raw.githubusercontent.com/python/cpython/main/PCbuild/sqlite3.vcxproj
- **macOS (python.org installer):** builds SQLite 3.53.4 with `-DSQLITE_ENABLE_FTS5 -DSQLITE_ENABLE_FTS4 -DSQLITE_ENABLE_FTS3_PARENTHESIS -DSQLITE_ENABLE_PERCENTILE -DSQLITE_ENABLE_RTREE` — https://raw.githubusercontent.com/python/cpython/main/Mac/BuildScript/build-installer.py
- **uv / python-build-standalone (Linux + macOS):** `-DSQLITE_ENABLE_FTS3 -DSQLITE_ENABLE_FTS3_PARENTHESIS -DSQLITE_ENABLE_FTS4 -DSQLITE_ENABLE_FTS5 -DSQLITE_ENABLE_RTREE -DSQLITE_ENABLE_GEOPOLY -DSQLITE_ENABLE_DBSTAT_VTAB` — https://raw.githubusercontent.com/astral-sh/python-build-standalone/main/cpython-unix/build-sqlite.sh
- **Linux distro Pythons** (Debian/Ubuntu `python3`, official `python:3.x` Docker images) link the distro `libsqlite3`; Homebrew's and Debian's builds report `ENABLE_FTS5` per https://discourse.brew.sh/t/sqlite3-with-fts5/5388 (Debian claim is from a search snippet — **verify per target image**).
- **Verified locally (2026-10-19):** the project's venv (`backend/venv`, Python 3.12.10, SQLite 3.49.1) reports `ENABLE_FTS3, ENABLE_FTS4, ENABLE_FTS5, ENABLE_MATH_FUNCTIONS`; `CREATE VIRTUAL TABLE … USING fts5(x, tokenize='trigram')`, `MATCH 'ello'`, indexed `LIKE '%o w%'`, and `bm25(u, 5.0, 1.0) … ORDER BY rank` all succeed.
- **How to check at runtime:** `'ENABLE_FTS5' in [r[0] for r in conn.execute('PRAGMA compile_options')]`, or simply attempt `CREATE VIRTUAL TABLE` and catch `OperationalError` (the behavioural test; Simon Willison's one-liner: https://til.simonwillison.net/sqlite/python-sqlite-environment). Recommend a startup probe that falls back to `LIKE` search with a logged warning if FTS5 is missing.
- FTS5 facts from https://www.sqlite.org/fts5.html : default tokenizer `unicode61` with `remove_diacritics 1` (set `2` for all Latin diacritics; Devanagari characters are token characters, so Hindi titles index fine but without stemming); **trigram tokenizer** gives substring matching ("Substrings consisting of fewer than 3 unicode characters do not match any rows"), case-insensitive by default, and "FTS5 tables that use the trigram tokenizer also support indexed GLOB and LIKE pattern matching" unless `remove_diacritics` is set; `bm25(tbl, w_col1, w_col2…)` per-column weights, "using 'rank' is faster than using bm25()"; **external-content tables** (`content='documents', content_rowid=…`) keep the index next to the real table and are synced with `AFTER INSERT/UPDATE/DELETE` triggers; contentless-delete needs SQLite ≥ 3.43.0. Trigram-tokenizer introduction version is not stated on the page (released in 3.34.0 per general knowledge — **unverified**).
- **Alembic caveat:** virtual tables and triggers must be created with `op.execute()`; SQLAlchemy has no FTS5 DDL.

### Hybrid: Chroma semantic + SQL keyword

- Chroma `where_document` supports `$contains`, `$not_contains` ("Full-text search is case-sensitive"), `$regex`, `$not_regex`, combinable with `$and`/`$or`, and can be passed in the same `query()` as `query_texts` and metadata `where`. The docs do not say whether it is an index or a scan — https://docs.trychroma.com/docs/querying-collections/full-text-search
- Reciprocal Rank Fusion: `score(d) = Σ_rankers 1 / (k + rank(d))`, `rank_constant` default 60; Elastic cites Cormack, Clarke & Buettcher SIGIR 2009 (https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf) — https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion . RRF is rank-only, so FTS5 `bm25` scores and Chroma distances need no calibration.
- Entity coverage for the palette: jobs, documents, channels (SQL/FTS5 on titles, topics, channel names); Q&As (SQL on question text + `qa_library_global` semantic); knowledge artifacts (`knowledge_report_md` in FTS5); notes (M5). All reads must go through `visibility_service.visible_video_ids` (D-063).

## M3 — Saved searches & alerts

### Scheduling per-user recurring work

Celery documentation (https://docs.celeryq.dev/en/stable/userguide/periodic-tasks.html , https://docs.celeryq.dev/en/stable/userguide/configuration.html):
- "You have to ensure only a single scheduler is running for a schedule at a time"; default `celery.beat:PersistentScheduler` "keeps track of the last run times in a local shelve database file" (`celerybeat-schedule`); "custom stores can also be used, like storing the entries in a SQL database" (django-celery-beat is the Django one).
- Embedded beat (`worker -B`): "not commonly used and for that reason isn't recommended for production use".
- `beat_max_loop_interval`: "Default: 0 … The default for this value is scheduler specific. For the default Celery beat scheduler the value is 300 (5 minutes), but for the django-celery-beat database scheduler it's 5 seconds because the schedule may be changed externally". I.e. a DB-backed scheduler must poll its store frequently.
- Celery FAQ: "Does Celery support Windows? No. Since Celery 4.x, Windows is no longer supported due to lack of resources. But it may still work" — https://docs.celeryq.dev/en/stable/faq.html . The project already runs the worker with `--pool=solo`; a separate `celery beat` process is the safe way on Windows dev (whether `-B` works with the solo pool is **unverified**).
- `celery.schedules.crontab(minute, hour, day_of_week, day_of_month, month_of_year)` exposes `is_due(last_run_at) -> (bool, next_seconds)` and `remaining_estimate(last_run_at) -> timedelta`; `celery.schedules.schedule(run_every)` for intervals — https://docs.celeryq.dev/en/stable/reference/celery.schedules.html . These can compute `next_run_at` for table rows with no extra dependency.

### "Materially changes the answer" — detection options

| Signal | Cost | Pros | Cons |
|---|---|---|---|
| Hash of normalised answer text | ~0 | trivial | LLM nondeterminism makes almost every run "changed" |
| New visible documents since last run (`document_visibility` grant timestamps / `job_videos` for scoped questions) | 1 SQL | **Skip the whole re-run** when nothing new is visible — removes most LLM spend | Only a pre-filter; new docs may be irrelevant |
| Jaccard / set-diff of cited `video_id`s (references are already extracted structurally by `qa_extract_references`) | ~0 | Deterministic, explainable ("2 new sources cited") | A new citation can carry the same claim |
| Cosine distance between old and new answer embeddings (same MiniLM embedder as `qa_library_global`) | 1 embed | Cheap, language-independent | No published threshold for "material"; must be calibrated on the app's own history (the Q&A library already holds every past answer) |
| LLM judge: old answer + new answer + new citations → `{changed: bool, what_changed: str}` | 1 small call (~$0.0002 on gpt-5-nano) | Produces the notification text | Only worth running when cheap signals are ambiguous |

## M4 — Question suggestions

### Prior art
- **Bing (Rosset et al., "Leading Conversational Search by Suggesting Useful Questions", The Web Conference 2020):** proposes *usefulness* beyond relevance ("provides valuable information for the user's next step"); a BERT ranker and a GPT-2 generator trained with multi-task learning and weak supervision from session next-turn behaviour; an online A/B test showed the more useful suggestions "received 8% more user clicks" — https://www.microsoft.com/en-us/research/publication/leading-conversational-search-by-suggesting-useful-questions/
- **NotebookLM:** "automatically suggests followup questions for you, based on your recent conversation history and the content of your sources" (documentation mirror: https://gist.github.com/dazzaji/5abdc3e7befabdee508ed0b298bfe3d3 ); no method disclosed.
- **Perplexity "Related":** follow-ups rendered under each answer, conditioned on query + sources + answer per third-party write-ups (https://llmpulse.ai/blog/how-perplexity-works/) — no official doc.
- **Google "People also ask", Bing/Copilot follow-ups:** **unverified** this session.

### Technique
1. Candidate generation from two pools: (a) nearest-neighbour *past questions* from `qa_library_global` (query = job topic / document title + knowledge-artifact topics; filter `tenant_id`), (b) LLM-generated questions grounded in the job report / `extracted_knowledge_json` topics (the app already extracts `{topics, concepts, events, facts}` per video).
2. Dedupe against questions already asked in this job (cosine on the same embedder).
3. Diversify with Maximal Marginal Relevance (Carbonell & Goldstein, SIGIR 1998 — DOI 10.1145/290941.291025, from memory); recent RAG work tunes the λ trade-off per query (DF-RAG, https://www.arxiv.org/pdf/2601.17212) and finds diversity raises recall (Salesforce, https://arxiv.org/abs/2502.09017v1).
4. Evaluate with impressions → clicks (CTR) and "asked-then-rated" signals; Rosset's +8% click lift is the benchmark shape.

### Embedding notes into retrieval and the 1.5× weight
- **Same collection with `source_type='note'` metadata** — one query, but notes are private per tenant while `videoresearchpro_global` chunks are shared (D-063) and the collection's chunking/ID scheme is per-video; a per-tenant metadata filter would then have to be applied to every query.
- **Separate `notes_global` collection** (`tenant_id`, `target_type`, `target_id`, `note_id` metadata; one document per note, not chunked, like `qa_library_global`) — second Chroma call, but same embedder so distances are directly comparable; trivial delete/upsert; mirrors the existing Q&A-library pattern (`chroma_service.get_qa_collection`).
- **Weight application:** D-068 already pre-registers the shape: retrieve `3 × top_k`, drop candidates failing `RAG_DISTANCE_THRESHOLD` on the *raw* distance, sort by `distance / weight`, keep `top_k` (docs/decisions.md §D-068). Notes get `weight = 1.5` → `distance / 1.5` on the merged list; the threshold still applies to the raw distance so an off-topic note cannot be pulled in. The app never passes `hnsw:space`, so collections use Chroma's default `l2` ("squared L2 norm"; alternatives `cosine`, `ip`) — https://docs.trychroma.com/docs/collections/configure . Dividing squared-L2 by 1.5 is monotone but not equivalent to a 1.5× cosine boost; keep the formula (consistency with channel weights) and measure with the E-1.14 blind-judge method before claiming it works.
- Prompts that read note text must carry a marker contract analogous to D-067's `VISUAL_ANNOTATION_CONTRACT` (e.g. `[NOTE by user @ …]`) so the model does not attribute the user's words to a speaker.

- **Notion:** `select`/`multi_select` options are rows `{id, name, color}`; "The option's ID … stays the same when its name changes"; names unique ignoring case; colours exactly `default, gray, brown, orange, yellow, green, blue, purple, pink, red` — https://developers.notion.com/reference/property-object
- **Readwise Reader tags/views:** docs 404'd — **unverified**.

### Modelling
- **Shelves ↔ jobs:** many-to-many (`shelf_jobs(shelf_id, job_id)`), Zotero semantics (a job in several shelves; deleting a shelf never deletes jobs). Nesting is optional; if added, copy Zotero's explicit "include subshelves" toggle rather than implicit roll-up.
- **Tags as rows, not free strings:** a `tags(id, tenant_id, name, color)` table with `UNIQUE(tenant_id, lower(name))` and a polymorphic `taggings(tag_id, target_type, target_id)` join gives stable ids across rename (Notion), global rename/merge (Raindrop), counts and colour; free-string JSON arrays make rename an `UPDATE` across every row and cannot enforce uniqueness in SQLite without JSON1 tricks. Palette: Notion's ten named colours as tokens in `theme.ts`, user picks a name not a hex.
- **Filtering Q&A by shelf:** comparable apps scope chat by container (NotebookLM notebook = its sources; Perplexity Projects = instructions + files; ChatGPT Projects — **unverified**). ## Recommendations

- **M1 Shelves/tags:** plain SQLAlchemy tables (`shelves`, `shelf_jobs`, `tags`, `taggings`), no new dependency, MIT-only stack unchanged — Zotero/Notion semantics (many-to-many shelves, tag rows with stable ids, ten named colours as theme tokens); shelf-scoped Q&A reuses the `video_id ∈ set` filter.
- **M2 Cmd-K:** `cmdk` 1.1.1 (MIT, 14.9 kB gz, unstyled, React 19 peer) with `shouldFilter={false}` over a `/api/v1/search?q=` endpoint backed by SQLite FTS5 external-content tables (verified present in the project's Python; startup probe + LIKE fallback) merged with Chroma via RRF; bind `Ctrl/Cmd+K` + `Ctrl+Alt+K` alternate and `/` only when no input is focused, with a settings toggle.
- **M3 Saved searches:** static Celery beat "tick" every 5 min scanning `saved_searches.next_run_at` (BSD-3 Celery only; `celery.schedules.crontab.remaining_estimate` for next runs; human cadences, no cron strings); gate re-runs on "new visible documents since last run", decide "material" by cited-set diff + answer-embedding distance with an LLM judge as tie-breaker; notify via existing SMTP + an in-app inbox over the existing WebSocket; defer web push (pywebpush MPL-2.0, HTTPS + service worker + iOS Home-Screen constraint). Upgrade path: RedBeat (Apache-2.0) if per-row beat entries become necessary.
- **M4 Suggestions:** new use case `qa_suggest_questions` on the cheapest configured model (gpt-5-nano ≈ $0.00014/batch; local via `LLM_USE_CASE_CONFIG`), candidates = `qa_library_global` nearest past questions + LLM generation from knowledge-artifact topics, MMR diversity, cached per `(job_id, latest_qa_id)`, logged impressions/clicks (Rosset 2020 usefulness framing).

## Risks and open questions

- **cmdk cadence:** no release since 2025-03-14 and 76 open issues; it is stable and tiny, but a React 20 break would wait on a volunteer maintainer. Fallback is Ariakit Combobox or React Aria Autocomplete (both unverified licence on-page; both believed permissive).
- **Inline-style purity vs. state selectors:** cmdk exposes selection as `data-*` attributes; either read state through its hook for per-item inline styles or accept one scoped `<style>` element — a small deviation from "100% inline styles" that should be an explicit decision.
- **FTS5 on Linux self-hosts:** depends on the distro libsqlite3; the startup probe and LIKE fallback are mandatory, and Alembic migrations must tolerate "no FTS5" (create the virtual table conditionally).
- **FTS5 and Hindi/transliteration:** `unicode61` tokenises Devanagari but does no stemming or transliteration folding; trigram helps romanised queries only for substrings. Semantic search (Chroma) covers the gap — RRF merge is the safety net.
- **Beat singleton on self-host:** the tick design tolerates duplicate ticks via row claiming, but two beats still double the DB load; document "run exactly one `celery beat`" in `start.ps1`. Whether `worker -B` works with `--pool=solo` on Windows is unverified.
- **Material-change threshold:** no published cosine threshold for "same answer"; must be calibrated on the app's own Q&A history and may differ by language. The pre-registered-measurement discipline of D-068 should apply.
- **Alert cost control:** without the "new visible documents" gate every saved search is an LLM call per cadence; with it, cost scales with ingest, not with the number of saved searches. Cap active saved searches per tier (ChatGPT caps 3/5/15; Perplexity 15 per conversation).
- **Web push on self-host:** needs HTTPS, a service worker, VAPID keys in `.env`, and iOS only via Home-Screen web apps; pywebpush is MPL-2.0 and single-maintainer. Defer.
- **Notes weight on squared-L2:** D-068's `distance / weight` was designed for channel weights on the same collection; applying it across two collections and on squared-L2 distances changes the effective boost. Measure; consider switching new collections to `cosine` (cannot be changed on the existing global collection without re-embedding).
- **Privacy of notes in retrieval:** notes are tenant-private; the `notes_global` collection must always be queried with a `tenant_id` filter and an empty visible set must retrieve nothing (D-063 rule).
- **Template placeholders:** if `search_instructions` may contain `{{topic}}`, decide on escaping and on what happens when a template's `preferred_channels` are later unsubscribed.
- **Unverified in this session (search budget exhausted / pages blocked):** Firefox `Ctrl+K` and `/` Quick Find bindings; Linear, Raycast, Readwise Reader palette and Views docs; ChatGPT Projects project-only memory; Jira work-item templates; Feedly AI / Elicit / Consensus alert mechanics; Google "People also ask" and Bing/Copilot follow-up generation; Logseq block model; Ariakit and React Aria licences (believed MIT / Apache-2.0); SQLite version that introduced the trigram tokenizer (believed 3.34.0); WP242 text (PDF not extractable).
