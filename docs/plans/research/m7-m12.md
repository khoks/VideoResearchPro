## Summary

1. **M7 needs no new infrastructure.** `scikit-learn>=1.1.0` is a core (non-extra) dependency of `sentence-transformers` 6.1.0, so TF-IDF/KMeans are already installed. Word clouds come from the existing `extracted_knowledge_json.topics/concepts`, not raw transcripts. Skip BERTopic (pulls hdbscan + umap/numba + pandas + plotly) and **skip YAKE — its repo LICENSE is AGPL-3.0-or-later** (PyPI classifier says GPLv3; either way copyleft).
2. **Word-cloud libraries:** `d3-cloud` 1.2.9 (BSD-3-Clause, published 2026-03-03, 2.9 KB gz) is the only maintained layout engine; `react-wordcloud` 1.2.7 is abandoned (last publish 2020, peerDep `react ^16.13.0`, will not resolve against React 19); `wordcloud` (wordcloud2.js) 1.2.3 MIT, 4.5 KB gz, last publish 2024-11-14.
3. **M8: keep reports as HTML, do not convert to Markdown.** `dompurify` 3.4.17 is `(MPL-2.0 OR Apache-2.0)` — confirmed dual, 11.5 KB gz, 0 deps — plus `html-react-parser` 6.1.8 (MIT, 10.5 KB gz, explicitly *not* a sanitizer) gives a native React reading view with a `replace` hook for citations and outline. `sanitize-html` is 50 KB gz and brings htmlparser2/postcss.
4. **Reading-view CSS in 2026:** `initial-letter` is still not Baseline (Firefox: none through 161; Safari needs `-webkit-`; Chrome 110+ partial) → use `::first-letter` float fallback. `hanging-punctuation` is Safari-only (17.9% global). Popover API is Baseline 2025 (93.6%). CSS anchor positioning is only partial everywhere (Chrome 125+, Firefox 147+, Safari 26+; 87.4%) → position hover footnotes with `getBoundingClientRect`, not `anchor()`. `text-wrap: pretty` — Chrome 117, Safari 26.0 (2025-09-15), **no Firefox** (87.6%); safe as progressive enhancement.
5. **M9: at Pratidhvani's scale (<5k nodes) every library works; the differentiator is API and bundle.** `sigma` 4.0.3 + `graphology` 0.26.0 + `@react-sigma/core` 6.0.0 (all MIT, ≈113 KB gz, WebGL, worker ForceAtlas2, Louvain communities) is the serious choice; `react-force-graph-2d` 1.29.2 (MIT, 60 KB gz, canvas) is the quick one. `cytoscape` 3.34.4 (MIT, 137 KB gz) has a WebGL *preview* since 3.31.0 (Jan 2025). `reagraph` (Apache-2.0) and `@antv/g6` (MIT) are 385–400 KB gz — too heavy for a lazy route.
6. **M10: no tour library.** Shepherd.js is **AGPL-3.0 from v14 onward** (13.0.3, 2024-08-05, was the last MIT release; 15.3.0 is current); Intro.js 8.6.0 is AGPL-3.0 with a paid commercial licence. NN/g's position (Feb 2023) is that overlay walkthroughs are "dramatically overused"; a plain stepper page + NN/g/Atlassian-style empty states fits the 100 %-inline-styles codebase. If coach marks are ever wanted: `driver.js` 1.10.2 (MIT, 7.7 KB gz, 0 deps). Store onboarding state in a **server column** (multi-device requirement).
7. **M11: opaque random tokens in a DB row, not JWT.** `secrets.token_urlsafe(32)` (256 bits; Python docs: 32 bytes "believed sufficient"; OWASP floor is 64 bits) stored **hashed** with `expires_at`/`revoked_at` gives revocation + expiry + audit for free. **Do not build on `python-jose`: 3.5.0 (2025-05-28, latest) carries CVE-2026-85394 (CVSS 9.3, published 2026-09-03, no fixed version)** — an incomplete fix of CVE-2024-33663 algorithm confusion. The project's auth already depends on it (`python-jose[cryptography]>=3.3.0`) — that is a cross-cutting risk; PyJWT 2.15.1 (MIT, 2026-09-28) is the usual replacement.
8. **Public share page hygiene:** `X-Robots-Tag: noindex` + `<meta name="robots" content="noindex">` (page must stay crawlable or the noindex is never seen), `Referrer-Policy: no-referrer`, token in path not query, `Cache-Control: no-store`, and serve the LLM HTML under `Content-Security-Policy: sandbox; default-src 'none'; …` (header only — `sandbox` is ignored in `<meta>`), ideally from a separate origin per Google's 2023 guidance. The ChatGPT incident (2025-07-31: ~4,500 shared chats in Google; OpenAI pulled the "discoverable" checkbox the same day) is the cautionary tale: no "make discoverable" toggle, noindex by default.
9. **M12 is almost entirely CSS with full support:** `svh/dvh` (Chrome 108, Firefox 101, Safari 15.4; 95.9%), `env(safe-area-inset-*)` (97.2%), ≥16 px inputs to stop iOS focus-zoom (do **not** use `maximum-scale=1` — iOS 10+ ignores it by default and it violates WCAG 1.4.4), WCAG 2.2 SC 2.5.8 = 24×24 CSS px AA (Apple HIG 44×44 pt, Android 48×48 dp + 8 dp gap). VisualViewport API (Baseline since Aug 2021) pins a bottom composer above the keyboard. Safari 26.0 made every Add-to-Home-Screen site open as a web app with **no manifest and no installability requirements** — a manifest is near-zero cost, a service worker is optional.
10. **Budgets and licences across the set:** web.dev's starting budget is <170 KB compressed critical-path resources / TTI <5 s on 3G; Vite 8 warns at 500 kB *uncompressed* per chunk and targets `baseline-widely-available` (chrome111/edge111/firefox114/safari16.4/ios16.4). Lazy-load M7/M9 routes. Licence traps: Shepherd ≥14 and Intro.js (AGPL), YAKE (AGPL), `pymupdf` already AGPL in `requirements.txt` (pre-existing), DOMPurify dual (elect Apache-2.0), vis-network dual, d3-force ISC, d3-cloud BSD-3-Clause.

**Approach comparison**

- **A. Sanitize + parse (recommended):** `DOMPurify.sanitize(html, {FORBID_TAGS:['style','script'], ADD_ATTR:['target']})` → `html-react-parser` with `replace` that (i) turns `<a href="…&t=123">` citations into a `<CitationLink>` that opens a hover popover with the quote/timestamp, (ii) collects `h2/h3` into the outline and injects ids, (iii) wraps `<table>` in a scroll container (WCAG 1.4.10). ≈22 KB gz total. Works on the existing report files unchanged. Note: DOMPurify keeps `<style>` by default **(verify against current DOMPurify defaults)** — forbid it so the reader's typography wins.
- **B. Convert reports to Markdown and reuse `react-markdown`:** lossy (tables, nested lists, figure/aside markup written by the LLM), needs a server-side converter and a migration of stored reports, and still needs sanitisation of raw HTML blocks. Not recommended.
- **C. rehype pipeline (`rehype-parse` → `rehype-sanitize` → `rehype-slug` → `rehype-react`):** same ecosystem as `react-markdown`, so a shared `components` map could serve both Markdown artifacts and HTML reports; size is comparable to A once `rehype-parse` (parse5) is counted. Reasonable second choice if M12 wants one component map for both content types.

### Reading-view UX patterns

- **Measure / rhythm:** Butterick: 45–90 characters per line including spaces (the "2–3 alphabets" test). [Practical Typography](https://practicaltypography.com/line-length.html). Implement as `max-width: 65ch` on the article column; `line-height` ≈1.5–1.6 for body (general practice).
- **Reading progress:** `scrollTop / (scrollHeight − clientHeight)` in a rAF-throttled scroll listener on the article's scroll container; render a 3 px bar under the top bar, `aria-hidden`. (Pattern; no primary source fetched.)
- **Sticky outline:** one `IntersectionObserver` over `h2,h3` with `rootMargin: "-10% 0px -80% 0px"` so the heading crossing the top band becomes "current"; outline in a `<nav aria-label="Outline">` with `aria-current="true"`. Keep the sticky panel from obscuring focus (WCAG 2.2 SC 2.4.11). (Pattern; no primary source fetched.)
- **Inline references on hover:** the Q&A reference shape `(document id, timestamp, quote)` maps directly to a popover card: title, `mm:ss`, quote, "open at timestamp". Also render them as a numbered endnote list for print and screen readers.
- **Print:** `@media print` hides sidebar/outline/progress, `a[href]::after { content: " (" attr(href) ")" }` for citations, `break-inside: avoid` on cards, `color-scheme: light` and `print-color-adjust: exact` for highlight backgrounds **(latter unverified)**.
- **Prior art (general knowledge, not fetched this session):** Medium (≈680 px measure, serif body, sticky reactions), Substack (progress + "share" bar), Readwise Reader (keyboard-first, highlights, per-document outline), Safari Reader (font/size/theme controls, strips chrome), NYT (drop caps, sticky share rail). Common denominators: single column, large measure, fixed small toolbar, typography controls (size/theme), hidden until needed.

### Scale guidance

- **~500 nodes:** anything, including SVG + `d3-force` (hover/labels as DOM text is an accessibility win).
- **~2,000 nodes:** canvas (`react-force-graph-2d`, cytoscape canvas); SVG interaction gets sluggish; run layout to convergence then freeze (`cooldownTicks`) rather than animating forever.
- **~10,000 nodes:** WebGL (sigma; cytoscape WebGL preview) and **layout off the main thread** (`FA2Layout` worker) or precomputed server-side and stored `(x, y)` per node. No trustworthy public benchmark at exactly 10k was found; the only hard numbers are cytoscape's above. The 100k-nodes-at-30–60 fps claim for sigma is a single vendor page **(unverified)**.
- **Pratidhvani's actual graph:** documents (hundreds–low thousands per tenant), Q&A exchanges (hundreds), topics/concepts (tens–hundreds) → comfortably <5k nodes, so the choice is about API ergonomics and bundle size, not raw capacity.

### What keeps it from being a hairball (prior art)

- **Obsidian graph view:** *local graph* with a **depth slider**, filters (search, tags, attachments, orphans, existing-only), **groups = colour by search query**, node size by inbound links, arrows, text-fade threshold, and exposed force sliders (center/repel/link/distance). Forum threads show the pain point is exactly "depth > 1 becomes overwhelming" and requests for saved per-page filters. [Obsidian help](https://obsidian.md/help/plugins/graph) · [forum](https://forum.obsidian.md/t/improved-filtering-of-local-graph/35937)
- **Connected Papers** (about page not fetchable; general knowledge, **unverified**): fixed ~40-paper neighbourhood around a seed, node size = citations, colour = year, edge = similarity not citation — i.e. *local, capped, encoded*.
- Design rules that follow: (1) default to the **local graph of the current document/Q&A at depth 1–2**, global view opt-in; (2) size by degree, colour by **Louvain community** (plus a shape/label so colour isn't the only channel — WCAG 1.4.1); (3) filters by node type (document / Q&A / topic), channel, date range; (4) hide degree-1 leaves and cap edges per node by weight; (5) labels only on hover/zoom; (6) click = focus + side panel, double-click = re-centre; (7) freeze layout after convergence.

### Accessibility

Canvas/WebGL graphs have no DOM, so pair the graph with (a) an equivalent **list/table view** (node list with degree, edge list) and (b) keyboard navigation over nodes (Tab into the graph, arrows move to neighbours, Enter opens) with a visible focus ring drawn on the canvas, and (c) a one-paragraph textual summary ("312 documents, 48 topics, 6 clusters; largest cluster …"). Vendors describe the same pattern (KeyLines keyboard/screen-reader guide; Oracle's toolkit moves focus between adjacent nodes/edges). WCAG 2.2 SC 2.5.7 Dragging Movements (AA) means pan/zoom/drag must also be achievable with buttons/keys. [Cambridge Intelligence](https://cambridge-intelligence.com/build-accessible-data-visualization-apps-with-keylines/) · [Oracle ACR](https://www.oracle.com/tw/corporate/accessibility/templates/t2-13982.html)

### Should there be a tour at all?

- NN/g, "Onboarding Tutorials vs. Contextual Help" (2023-02-12): walkthroughs are "push revelations" — interrupting, skipped, forgotten, "dramatically overused"; prefer pull revelations (tooltips, coach marks tied to context, **step-by-step task-flow wizards**), easy to dismiss and easy to find again, progressive disclosure. [NN/g](https://www.nngroup.com/articles/onboarding-tutorials/)
- M10 as specified ("pick channels → run a first job → see the result") *is* a task-flow wizard, i.e. a page with steps and real actions, not an overlay. That needs no library — a `Stepper` component with inline styles and the existing job/channel mutations.

### Empty-state guidance

- NN/g (2021-09-19): every empty container needs a **system-status message** (empty vs loading vs error — never "No records" while loading), **learning cues** (what this area is for; more memorable than forced tutorials), a **direct pathway** (button/link that starts the task in place), and progress indicators; "Do not default to totally empty states." [NN/g](https://www.nngroup.com/articles/empty-state-interface-design/)
- Atlassian Design System: header (required), description, one primary action (+ secondary/link), optional spot illustration; sentence case; short; avoid sending people elsewhere; tone matches scenario (first-time = motivating, no-results = neutral with next step); widths 464 px wide / 304 px narrow. [Atlassian](https://atlassian.design/components/empty-state/usage)
- Shopify Polaris empty state: page now 301s into the JS-only `shopify.dev/docs/api/polaris` app — **could not fetch**; component exists (heading + body + primary action + image).

### Activation metrics

- Lenny's Newsletter survey (2022-10-25, 500+ respondents): SaaS activation median 30 %, average 36 %; a good milestone predicts retention ≥2× and is something the team can influence; examples "first design published and shared", "first 5 survey responses". [source](https://www.lennysnewsletter.com/p/what-is-a-good-activation-rate)

Linear/Notion/Slack first-run checklists — **(unverified; general knowledge)** — all keep a persistent, dismissible checklist in the sidebar rather than a modal.

Put the token in the **path** (`/s/<token>`), not a query string (query strings end up in logs and analytics), and never reuse the existing `?token=<JWT>` iframe pattern for public links.

### Response headers for the public route

- `X-Robots-Tag: noindex, nofollow` **and** `<meta name="robots" content="noindex">` — Google only honours noindex if it can crawl the URL, so do **not** also block `/s/` in robots.txt. [Google](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag)
- `Referrer-Policy: no-referrer` (the browser default `strict-origin-when-cross-origin` already strips path+query cross-origin, but `no-referrer` also stops same-origin leakage into any analytics). [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy)
- `Cache-Control: private, no-store` so revocation is immediate at CDNs/proxies.

### Isolating the LLM-written HTML

- `Content-Security-Policy: sandbox` applies iframe-style restrictions to a top-level document (opaque origin, no scripts/forms/popups unless allowed); **header only — not supported in `<meta>`**; Baseline widely available since Nov 2016. Combine with `default-src 'none'; style-src 'unsafe-inline'; img-src https: data:` to stop exfiltration via `<img src>`. [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)
- Google's 2023 guidance for user-hosted content: `sandbox` + `default-src 'none'` + `Cross-Origin-Resource-Policy: same-site`, ideally a **separate origin/domain** for user content, because not all browsers process-isolate sandboxed documents. [Google Security Blog](https://security.googleblog.com/2023/04/securely-hosting-user-data-in-modern.html)
- If embedding instead: never combine `allow-scripts` with `allow-same-origin` on a sandboxed iframe. [web.dev](https://web.dev/sandboxed-iframes/)
- Simplest correct shape for this app: the public React route fetches the report body JSON and renders it through the **same DOMPurify + html-react-parser reader as M8** (so sharing inherits the reading view), while the raw-HTML endpoint (if any) carries `CSP: sandbox; default-src 'none'`.

### What others do (revocation / expiry UX)

### Takedown basics

- **US, 17 U.S.C. §512(c):** safe harbour needs (1) no actual/red-flag knowledge or expeditious removal on gaining it, (2) no direct financial benefit where you control the activity, (3) expeditious removal on a compliant notice (elements in §512(c)(3): signature, work, location, contact, good-faith statement, perjury statement), (4) a **designated agent registered online with the Copyright Office** (paper no longer accepted) and published on the site, (5) a **repeat-infringer policy** (§512(i)). Counter-notice (§512(g)): forward to complainant, restore in **10–14 business days** unless sued. [Cornell LII](https://www.law.cornell.edu/uscode/text/17/512) · [Copyright Office directory](https://www.copyright.gov/dmca-directory/)
- **India, IT Rules 2021 Rule 3(1)(d), amended 2025-10-22 (effective 2025-11-15):** remove within **36 hours** of a court order or a reasoned written intimation from a Joint Secretary-level officer (DIG-level for police); notices must state legal basis + URL; Secretary-level monthly review; the clause protecting voluntary removals was dropped; missing the window risks s.79 safe harbour. [MediaNama](https://www.medianama.com/2025/10/223-content-takedown-rules-online-platforms-36-hr-deadline-officer-rank/) · [FPF](https://fpf.org/blog/india-massive-overhaul-of-digital-regulation-with-strict-rules-for-take-down-of-illegal-content-and-automated-scanning-of-online-content/)
- Minimum viable workflow: a `/legal` page with a contact, an admin action "revoke share + mark report restricted + record notice", and a log table — the same `report_shares.revoked_at` column serves both.

### Should sharing ship before billing / abuse prevention? (trade-offs only)

- **For shipping first:** reads are cheap (static HTML, no LLM); it is the single highest-leverage growth surface for a research product; self-hosters want it regardless of SaaS; the reader (M8) and the share page can be the same component.
- **Against:** a public, unauthenticated route is new attack surface (token enumeration — mitigated by 256-bit tokens; scraping; **using your domain to host arbitrary LLM-written content**); reports quote transcripts, so copyright/ToS exposure becomes public rather than private; no abuse-signal or reporting pipeline exists; rate limiting is currently per-IP/per-user tiers (E-5.5) with no per-share quota; free tier + public hosting invites spam.
- **Cheap mitigations if it ships early:** opt-in per report, default **off**; default expiry (e.g. 30 days) with explicit "no expiry" choice; per-tenant cap on active shares; `noindex`; per-IP rate limit on `/s/`; `SHARING_ENABLED` env kill switch; "Report this page" link; view counter visible to the owner; revoke-all on account lock.

### Touch targets

- **WCAG 2.2 SC 2.5.8 Target Size (Minimum), AA:** ≥24×24 CSS px, or smaller if a 24 px-diameter circle centred on it doesn't intersect another target's circle; exceptions: inline (in a sentence / line-height-constrained), user-agent default, essential, equivalent control elsewhere. ### Swipe / back-gesture conflicts

- iOS Safari's edge swipe navigates history; any horizontal gesture that starts within ~20 px of the screen edge (drawers, carousels, graph pan in M9) will lose to it. MDN's `overscroll-behavior` page doesn't cover history gestures; the claim that `overscroll-behavior-x: none` disables Chromium's pull-navigation is **unverified**. Standalone (home-screen) web apps behave differently **(unverified)**. Design rule: no edge-anchored horizontal gestures; a hamburger button, not a swipe, opens the 240 px sidebar on phones.

### Typography on phones

- Fluid type: `font-size: clamp(1rem, 0.92rem + 0.4vw, 1.125rem)`; measure `max-width: 65ch`; `text-wrap: pretty` (Chrome 117+, Safari 26+, not Firefox) and `text-wrap: balance` on headings (Baseline). WCAG 1.4.10 Reflow: content must work at **320 CSS px** without 2-D scrolling (data tables exempt but must sit in their own scroll container; headings/search/pagination around them still reflow). [W3C](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
- Knowledge artifacts (Markdown via `react-markdown`) and Q&A answers (references as chips) reuse the same `components` map so phone rules apply once.

### PWA — is it worth it for a reading app?

- **Safari 26.0 (2025-09-15):** every site added to the Home Screen opens as a web app by default (user can opt out per site), **manifest optional** (honoured if present, incl. icons), **no installability requirements**. [WebKit](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)
- Still missing on iOS: `beforeinstallprompt` (no auto-prompt), Background Sync, Web Bluetooth, home-screen widgets; push works since 16.4 only from a user gesture; Declarative Web Push since 18.4; the "50 MB cache / 7-day eviction" folklore is disputed between 2026 sources **(unverified)**. [mobiloud](https://www.mobiloud.com/blog/progressive-web-apps-ios/) · [tappwa](https://tappwa.com/blog/ios-pwa-limitations-2026) · [synthetixis](https://synthetixis.com/writing/pwa-ios-2026)

A service worker (offline reports) is optional and complicates JWT-gated fetches and report invalidation; defer unless offline reading becomes a stated requirement.

## Risks and open questions

1. **`python-jose` critical CVE (2026-85394, no fix).** Independent of M11, auth tokens are minted/verified with it today. Confirm `jwt.decode(..., algorithms=["HS256"])` is pinned everywhere; schedule a PyJWT migration. This is the most consequential finding in this research.
2. **Share tokens vs the existing `?token=<JWT>` iframe pattern.** If M8 removes the iframe, the JWT-in-query endpoint for reports can be retired, closing a log-leak surface; if it stays, M11 must not be built on it.
3. **Public hosting of LLM-written HTML on the app's origin.** Even sanitised, a public page is content "published by Pratidhvani" — brand, legal (DMCA/IT Rules timelines above) and SEO exposure. A separate origin (`share.<domain>`) is Google's recommendation and costs one DNS record + CORS.
4. **Copyright in reports.** Reports quote transcripts; a public share makes YouTube-derived text public. Needs a product decision (quote-length limits, attribution block, takedown contact) before sharing ships.
5. **`initial-letter` in Firefox** — still absent in 161; the fallback must be the design, not the exception.
6. **`text-wrap: pretty` in Firefox** — absent; fine as enhancement, but screenshots will differ per browser in Playwright visual tests.
7. **Graph accessibility** is real work (table view, keyboard model, summary text); budget it, or the graph fails 1.1.1/2.1.1/2.5.7.
8. **Graph data model** — document↔Q&A edges exist (references), document↔topic edges exist (knowledge JSON), but Q&A↔topic and topic↔topic (co-occurrence) edges must be derived; decide whether to persist a `graph_edges` table or compute per request (fine at <5k nodes).
9. **M7 stance data** — I did not re-verify in the repo that per-document stance/sentiment columns exist and are populated for subscription-ingested videos (which have no report); if stance is only computed for job documents, channel time series will be sparse.
10. **Onboarding + rate limits** — a first job that hits the transcript throttle (3 s/video) or Whisper fallback can take many minutes; the wizard's "see the result" step must tolerate `awaiting_approval`/long `extracting` states or seed a deliberately tiny first job.
11. **Shepherd.js exact licence-change version/date** unconfirmed (npm has 13.0.3 MIT → 15.0.0 AGPL; 14.0.0 absent). Irrelevant if no tour library is used.
12. **Vite 8 / Rolldown** — `manualChunks` lives under `build.rolldownOptions`; existing docs/snippets assume Rollup. Verify when adding lazy vendor chunks.
